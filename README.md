# AI-Augmented Zero Trust Framework for BFSI
### A Hybrid Supervised–Unsupervised Approach to Adaptive Access Control

---

## Abstract

The Banking, Financial Services, and Insurance (BFSI) sector is a prime target for cyberattacks due to the high value of its data and transactions. Traditional perimeter-based security assumes implicit trust inside the network, an assumption that fails against insider threats, credential theft, and lateral movement. Zero Trust Architecture (ZTA) addresses this by enforcing continuous verification of every access request.

This project develops an **AI-augmented Zero Trust framework** that combines a **supervised Gradient Boosting Classifier** with an **unsupervised Autoencoder** to make adaptive, risk-aware access decisions. Using two synthetic datasets of 200,000 access logs each — one generated by a Traditional rule-based ZTA and one by an AI-driven ZTA — we perform extensive exploratory data analysis, engineer 10 risk-aware features, and train multiple models. The supervised Gradient Boosting model achieves **97.99% accuracy** on the AI-ZTA dataset. The Autoencoder detects behavioural anomalies using reconstruction error with a 90th-percentile threshold. In the hybrid, anomalies trigger escalation of `allow` → `step-up`, and further to `restrict` when the composite risk score is in the top 10%. This hybrid trades ~0.5% accuracy for significantly better safety on high-risk sessions — the ideal trade-off for Zero Trust in BFSI.

**Keywords:** Zero Trust Architecture, BFSI Security, Hybrid Model, Gradient Boosting, Autoencoder, Anomaly Detection, Adaptive Authentication, Risk-Based Access Control, Exploratory Data Analysis.

## 1. Introduction

### 1.1 Context

The BFSI sector handles sensitive financial data, personally identifiable information (PII), and high-value transactions. A single breach can cause financial loss, regulatory penalties, and reputational damage. Traditional security models assume users inside the network are trustworthy — an assumption broken by modern threats:

- **Insider threats** — legitimate users misusing access
- **Credential theft** — stolen passwords or tokens
- **Lateral movement** — attackers pivoting from a compromised device
- **Supply chain attacks** — vendors with weak security postures

### 1.2 Zero Trust Architecture (ZTA)

Zero Trust eliminates implicit trust. Every access request must be authenticated, authorised, and continuously validated based on context. Core principles (NIST SP 800-207):

1. **Verify explicitly** — Use all available data points (identity, device, location, behaviour).
2. **Use least privilege** — Grant only the minimum necessary access.
3. **Assume breach** — Design as if the network is already compromised.

In practice, a ZTA engine computes a **trust score** and maps it to an action: `allow`, `step-up` (additional authentication), `restrict` (limited access), or `block`.

### 1.3 Why AI?

Rule-based ZTA engines are deterministic and auditable but static — they struggle with novel attacks and complex feature interactions. Machine learning can learn these patterns from historical data, but pure ML models can be unpredictable and difficult to explain. A **hybrid model** — combining supervised and unsupervised learning — offers the best of both worlds: accurate classification from labelled data plus behaviour-aware safety from unsupervised anomaly detection.

### 1.4 Project Objectives

1. Perform comprehensive EDA on two parallel synthetic ZTA datasets (AI-driven and Traditional).
2. Engineer 10 risk-aware features including a composite risk score.
3. Train and compare three supervised classifiers (Random Forest, Gradient Boosting, Logistic Regression).
4. Implement two unsupervised anomaly detectors (Isolation Forest, Autoencoder).
5. Design and evaluate a hybrid model combining the best supervised classifier with the Autoencoder.
6. Document the framework for BFSI deployment.

## 3. Literature Review

### 3.1 Zero Trust Models

- **NIST SP 800-207** defines ZTA with Policy Decision Points (PDP) and Policy Enforcement Points (PEP).
- **Forrester's Zero Trust eXtended (ZTX)** extends ZTA to data, workloads, and automation.
- **Google BeyondCorp** shifted access control from the network perimeter to the user and device.

### 3.2 AI in Security

- **Anomaly detection:** Autoencoders, Isolation Forests, one-class SVMs.
- **Risk scoring:** Gradient boosting (XGBoost, LightGBM) for tabular risk prediction.
- **Hybrid systems:** Combining supervised and unsupervised learning is common in fraud detection and intrusion detection.

### 3.3 Gap Addressed

Most published ZTA implementations are purely rule-based or purely supervised. This project implements and evaluates a **hybrid supervised–unsupervised** model, demonstrating how classification and anomaly detection can be integrated for BFSI-grade access control.

## 6. Feature Engineering and Preprocessing

### 6.1 Timestamp Features

```python
df['timestamp'] = pd.to_datetime(df['timestamp'], errors='coerce')
df['hour'] = df['timestamp'].dt.hour
df['day_of_week'] = df['timestamp'].dt.dayofweek
df['is_weekend'] = df['day_of_week'].isin([5, 6]).astype(int)
```

- `hour` — time-of-day pattern
- `day_of_week` — weekday behaviour
- `is_weekend` — binary weekend flag

### 6.2 Categorical Encoding

| Feature | Mapping |
|---|---|
| `location_risk` | low=1, medium=2, high=3 |
| `network_risk` | low=1, medium=2, high=3 |
| `device_posture` | compliant=0, unknown=1, jailbroken=2 |
| `auth_method` | password=0, biometric=1, mfa=2 |
| `role` | it_admin=3, manager=2, auditor=2, support/corporate/retail/teller=1 |

Risk-aware ordinal encoding preserves domain semantics.

### 6.3 Missing Value Handling

```python
df.fillna({
    'location_risk_enc': 1, 'network_risk_enc': 1,
    'device_posture_enc': 1, 'auth_method_enc': 0,
    'role_risk': 1, 'hour': 12
}, inplace=True)
```

Conservative defaults: unknown device, password auth, midday — to avoid underestimating risk.

### 6.4 Behaviour Feature Normalisation

```python
scaler = MinMaxScaler()
df_ai[['behavior_anomaly_norm', 'historical_trust_norm']] = scaler.fit_transform(
    df_ai[['behavior_anomaly', 'historical_trust']]
)
df_traditional[['behavior_anomaly_norm', 'historical_trust_norm']] = scaler.transform(
    df_traditional[['behavior_anomaly', 'historical_trust']]
)
```

Scaler is fit only on AI-ZTA to prevent leakage; the same parameters are applied to Traditional ZTA.

### 6.5 Composite Risk Score (Core Feature)

```python
df['risk_score'] = (
    0.30 * df['behavior_anomaly_norm'] +
    0.20 * df['location_risk_enc'] +
    0.20 * df['network_risk_enc'] +
    0.15 * df['device_posture_enc'] +
    0.10 * df['role_risk'] -
    0.15 * df['auth_method_enc']
)
```

**Weight Rationale:**

| Feature | Weight | Reason |
|---|---|---|
| `behavior_anomaly` | +0.30 | Highest — behaviour is the strongest risk signal |
| `location_risk` | +0.20 | Environmental threat |
| `network_risk` | +0.20 | Environmental threat |
| `device_posture` | +0.15 | Device trust matters |
| `role_risk` | +0.10 | Least privilege |
| `auth_method` | −0.15 | Strong auth reduces risk |

This composite score is a key engineered feature for the model.

### 6.6 Action Label Encoding


Encoder is fit on AI-ZTA and applied to Traditional ZTA for consistency.

#### 7.2.2 Autoencoder (Chosen Anomaly Detector)

```python
input_dim = X_train_scaled.shape[1]

input_layer = Input(shape=(input_dim,))
encoded = Dense(8, activation='relu')(input_layer)
encoded = Dense(4, activation='relu')(encoded)
decoded = Dense(8, activation='relu')(encoded)
decoded = Dense(input_dim, activation='linear')(decoded)

autoencoder = Model(inputs=input_layer, outputs=decoded)
autoencoder.compile(optimizer='adam', loss='mse')

autoencoder.fit(
    X_train_scaled, X_train_scaled,
    epochs=50, batch_size=32, validation_split=0.2, verbose=1
)
```

**Architecture:**

```text
Input (10) → Dense(8, ReLU) → Dense(4, ReLU) → Dense(8, ReLU) → Dense(10, Linear)
```

Bottleneck (4 neurons) forces the model to compress and reconstruct. High reconstruction error = anomaly.

**Threshold:**

```python
recon_train = autoencoder.predict(X_train_scaled)
mse_train = np.mean(np.power(X_train_scaled - recon_train, 2), axis=1)
threshold = np.percentile(mse_train, 90)   # 90th percentile
```

- 90th percentile of training reconstruction error
- ~10% of training data flagged as anomalous by design
- Tunable hyperparameter (90 / 95 / 99)

**Why Autoencoder over Isolation Forest:**

- Learns non-linear relationships via neural network
- Handles high-dimensional feature interactions
- Reconstruction error is a natural anomaly signal

## 8. Hybrid Model Architecture

### 8.1 The Two Components

| Component | Type | Model | Purpose |
|---|---|---|---|
| Component 1 | Supervised | Gradient Boosting Classifier | Predicts access action |
| Component 2 | Unsupervised | Autoencoder | Detects behavioural anomalies |

### 8.2 Hybrid Combination Logic

```python
# Step 1: Supervised prediction
gb_ai_pred = gb_ai.predict(X_ai_test)

# Step 2: Unsupervised anomaly flag
ae_anomaly_flag = (mse_test > threshold).astype(int)

# Step 3: Labels
allow_label    = action_encoder.transform(['allow'])[0]
stepup_label   = action_encoder.transform(['step-up'])[0]
restrict_label = action_encoder.transform(['restrict'])[0]

# Step 4: Escalation rules
hybrid_pred = gb_ai_pred.copy()
high_risk_threshold = X_ai_test['risk_score'].quantile(0.9)

for i in range(len(hybrid_pred)):
    if ae_anomaly_flag[i] == 1:
        # Escalate "allow" → "step-up"
        if hybrid_pred[i] == allow_label:
            hybrid_pred[i] = stepup_label

        # If also high-risk → "restrict"
        if X_ai_test.iloc[i]['risk_score'] > high_risk_threshold:
            hybrid_pred[i] = restrict_label
```

### 8.3 Decision Table

| Base Prediction | Anomaly Flag | Risk Score | Hybrid Action |
|---|---|---|---|
| allow | 0 | any | allow |
| allow | 1 | low | step-up |
| allow | 1 | top 10% | restrict |
| step-up / restrict / block | any | any | unchanged |

### 8.4 Why This Hybrid Design?

| Reason | Explanation |
|---|---|
| Supervised handles known patterns | Gradient Boosting learns from labelled decisions with 98% accuracy |
| Autoencoder catches novel anomalies | Flags sessions that look normal but are behaviourally unusual |
| Escalation, not hard block | step-up preserves usability while adding verification |
| Tiered response | step-up for isolated anomalies; restrict when combined with high risk |
| Aligns with Zero Trust | Continuous verification of even "allow" decisions |

- `device_posture` and `auth_method` influence conditional decisions.

- Supervised-only can over-allow on unfamiliar patterns.

## 11. Limitations

- **Synthetic data:** Real logs have noise, missing values, and different distributions.
- **No concept drift handling:** Model must be retrained periodically.
- **Autoencoder threshold sensitivity:** 90th percentile is heuristic; optimal threshold may vary.
- **Limited interpretability:** Neural network component is less interpretable than tree models.
- **No temporal modelling:** LSTM/GRU for sequence-based anomaly detection is future work.
- **No deployment:** Project ends at model training.

## 13. Conclusion

This project demonstrates that a hybrid supervised–unsupervised model can significantly improve Zero Trust access control for BFSI. Using 200,000 synthetic logs per dataset and 10 engineered features, the Gradient Boosting classifier achieved 97.99% accuracy on AI-ZTA data. The Autoencoder added unsupervised anomaly detection to escalate risky "allow" predictions to step-up or restrict. The hybrid trades ~0.5% accuracy for substantially better safety on high-risk sessions — exactly the trade-off Zero Trust demands. The framework is interpretable, deployable, and extensible, providing a practical solution for BFSI security.
